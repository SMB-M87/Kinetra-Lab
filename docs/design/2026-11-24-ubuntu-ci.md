## Problem

Kinetra's CI runs on pull requests and again on pushes to `main`. The same push starts a separate workflow that opens the pointer pull request in Lab. Lab already evaluates the changes between the two engine commits, but classifies Codex settings as build inputs. Lab #124 rebuilt because of `.codex/config.toml`; Lab #125 rebuilt because simulation and runtime sources changed.

Both Linux jobs already build and test on Ubuntu 24.04. Arch currently supplies the strict diagnostics and format check, and its toolchain also builds the Windows release zip.

## Goals and non-goals

- Kinetra #62 validates pull requests once, uses Ubuntu LTS for the strict Linux checks and synchronizes Lab immediately after a merge. Its docs describe Linux source builds and its roadmap drops Fedora CI.
- Lab #127 uses Ubuntu LTS for Linux checks and the Windows cross build, and runs native Windows checks for build-affecting changes. A pointer update with identical engine content or build-free changes qualifies for the documentation check. The Windows ZIP passes the DLL import check and the Lab roadmap drops the Linux release.
- The scope covers CI, release infrastructure and contributor guidance. Application behavior, simulation results and the Windows artifact format are outside this change.

## Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Kinetra CI events | Pull requests | The pull request covers the merge candidate. |
| Release and Fedora backlog | Drop the Linux release and Fedora CI work | The requested Linux distribution model is source builds and validation on Ubuntu LTS. |
| Lab pointer trigger | Start directly after the merge, with hourly recovery | Lab can follow Kinetra promptly. |
| Lab checks when engine sources change | Run full Lab CI. Allow the lightweight check for identical trees and changes that cannot affect Lab's build or tests. | Engine tests and Lab integration cover different behavior. |
| Windows packaging host | Cross-build from Ubuntu 24.04 | Ubuntu's MinGW-w64 can produce the Windows zip and run the DLL import check. |
| Linux toolchain | Ubuntu 24.04 with the existing strict checks and pinned clang-format 23.1.5 | Ubuntu becomes the reference for compiler warnings and the formatter keeps its existing version. |

## Design

Both pull request workflows use a single Ubuntu Linux job with the distro build packages and a pinned formatter installed with PyPI. The required `CI / checks` status accepts the full Linux result or a successful documentation check for an eligible diff. Lab also runs its native Windows job for changes that need a build. Kinetra's separate pointer workflow continues to synchronize Lab directly after a merge and to catch up hourly.

Lab's shared CI and release script adds exactly `.codex/config.toml` to the existing list of build-free Kinetra paths. It compares both recorded engine commits. Source and test inputs, missing commits and comparisons that fail still trigger a build.

The release workflow uses Ubuntu's POSIX MinGW-w64 package with the existing `windows` preset, static compiler runtime and DLL import check. The pre-release, tag and manual triggers continue to publish or build the Windows zip from the requested commit.

## Affected areas

- Kinetra #62 updates `.github/workflows/ci.yml`, Linux setup and testing docs, the shared verify skill and the engine roadmap. The separate `lab-pointer.yml` handles synchronization.
- Lab #127 updates `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `tools/release/needs_build.sh` and the Linux, Windows and Demo build guidance, including the warning policy comments in `CMakeLists.txt`.

## Test plan

- Check the workflow events and the required `CI / checks` result for both normal and skipped builds.
- Reproduce the unnecessary Lab build with the #124 pointer range. Use #125 as the engine-source case, and verify that an unresolved range still takes the conservative path.
- Run the pinned formatter and documentation checks. Verify the Ubuntu headless, graphics and consumer checks, including the native Windows CI job in Lab.
- If the Windows packaging host changes, cross-build the applications, run the DLL import check and inspect the contents of the release zip.

## Verification

- Before the fix, `bash tools/release/needs_build.sh '00b55e4^1' 00b55e4` returned `true` for the Codex settings range from Lab #124. With the fix it returns `false`. The engine source ranges in Lab #125 and #126 return `true`.
- Local Git fixtures confirmed the lightweight decision for an identical tree and full verification for an unresolved commit, another Codex file, README test input and engine source.
- `actionlint`, documentation link checks and Bash syntax checks passed for the changed workflows and script. Local checks exercised the pull request triggers, push-based pointer synchronization and required status logic.
- Kinetra's `cmake --workflow --preset ci` passed all 308 tests in Ubuntu 24.04 with GCC 13.3.0 and warnings treated as errors.
- The format check passed on both main branches with clang-format 23.1.5 from PyPI.
- Ubuntu 24.04 with `g++-mingw-w64-x86-64-posix` built all four Windows executables via `cmake --preset windows` and `cmake --build --preset windows --target kinetra kinetra_demo kinetra_dotio kinetra_i4sim`. The existing DLL import check passed. `tools/release/package_windows.sh` created the zip with all four executables, SDL2.dll, the blueprints and the licenses.

## Review

The filter stays specific to one configuration file. GitHub still receives the required status for a lightweight pull request, and native Windows runs for changes that can affect the build. Release packaging and publishing use their existing triggers and artifact names.

Round 1 aligned the remaining Ubuntu warning and characterization guidance, and recorded the acceptance criteria and affected areas per repository.
